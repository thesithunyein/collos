# Code of conduct

## Why this file exists

Collos is software about caring for people who cannot always speak for
themselves. The project asks for care in its subject matter, so it should not
need a separate argument for showing care in the way it is discussed. This is
written for Collos rather than copied from a template, because a code of conduct
that was not read before it was pasted is not a code of conduct — and because the
best-known template is used here by reference below, not reproduced with
half-remembered wording.

## What is expected

- **Be straight about the product.** This project's whole standard is that nothing
  may describe a feature that does not work. That applies to conversations too:
  report what you actually saw, say when you are unsure, and do not file a bug as
  a certainty you have not checked.
- **Assume the person on the other end is tired.** Care work happens at the end
  of long days. Terse is fine; contemptuous is not.
- **Criticise the work, not the person.** "This contradicts the FAQ" is
  useful. "This is obviously AI slop" is not, and neither is the reverse — a
  contributor's work is not above review because it took a long time.
- **Respect the scope of the product.** Collos is care coordination. It is not
  medical advice, and no feature, pull request or issue should push it toward
  giving one — no dosages, no diagnoses, no clinical claims, no "the app will
  remind you to take your medication" promises. See the [README](README.md) for the
  honesty rules the codebase is held to.
- **Write for a reader.** Issues and pull requests here are read by people
  deciding whether to trust an app with their family's daily plan. Say what
  changed, why, and what you verified. Say what you did **not** verify.

## What is not acceptable

Harassment, insults, slurs, sexual attention or imagery, deliberate
misgendering, sustained disruption of discussion, publishing someone's private
information, or dismissing a report of any of the above. Also not acceptable:
using this project's issues, discussions or pull requests to promote unrelated
products, or to make medical claims about Collos.

This list is shorter than the Contributor Covenant because it is specific to this
project. If you want a widely adopted, longer statement of the same principles,
the [Contributor Covenant](https://www.contributor-covenant.org/) is the reference
document, and behaviour that would breach it breaches this file.

## Scope

This applies in every project space: issues, pull requests, commit messages,
discussions, and any place where someone is representing the project. It also
applies when someone is contacted privately about project work.

## Reporting

Email **sithunyein.mailto@gmail.com** with the subject line `CONDUCT — Collos`.
Reports are read by the maintainer and are not discussed with the person they are
about until a decision has been made. If the report is about the maintainer, say
so in the message; the same standard applies, and the honest answer is that an
independent project has limited remedies — you will at least get a straight reply
and a decision, not silence.

## Enforcement

Depending on severity and pattern, a response may be:

1. A private note explaining what was unacceptable and what is expected instead.
2. A public correction, if the behaviour happened in public and the record
   matters.
3. A temporary block from project spaces.
4. A permanent block.

Serious one-off behaviour — threats, harassment, publishing private information —
skips to step 3 or 4.
